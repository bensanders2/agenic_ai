AI Agentic Design Patterns with AutoGen

DeepLearning.AI — Instructors: Chi Wang (Microsoft) & Qingyun Wu (Penn State)

Course Overview

AutoGen is a multi-agent conversational framework for building complex AI applications using agentic design patterns. Agents can be assigned different roles, personas, tasks, and capabilities — and can iteratively review and improve results.

Motivating Example

Financial data analysis: a task requiring code to collect/analyze share prices, then synthesize findings into a report. A multi-agent system handles this by spinning up specialized agents (researcher, data collector, co-writer, executor) that collaborate and self-critique until the output meets standard.

Course Lessons & Design Patterns

Lesson 1 — ConversableAgent (Two-Agent Conversation)

Core building block. Demonstrated via a two standup comedian agents interacting with each other.

Lesson 2 — Sequential Chats

Multi-agent interaction pattern where agents work step-by-step through a task list in order. Use case: customer onboarding application.

Lessons 3 & 4 — Reflection Framework + Nested Chats

An agent given a task spins up its own sub-agents, iterates with them, then returns a final result — analogous to a managed agent who can in turn manage their own agents.

  • Use case 1: multi-agent blog post writing and revision
  • Use case 2: conversational chess game

Lesson 5 — Tool Use & Code Execution

Tool use: provide a user-defined function to an agent (e.g., a function to validate chess move legality).

Code execution: when no predefined function exists, the agent writes the code it needs, verifies it, and executes it — optionally in a sandbox. Both patterns demonstrated in the financial analysis example.

Lesson 6 — Custom Multi-Agent Group Chats

Best practices for orchestrating group chats with multiple agents. A planning agent is added to decide the sequence of actions (gather data → analyze → write → revise) and control work handoffs between agents. Use case: generating a detailed report.

Key Concepts

  • ConversableAgent — base agent class in AutoGen
  • Sequential chats — ordered, step-by-step task execution across agents
  • Nested chats — agent-within-agent orchestration for complex subtasks
  • Tool use — injecting external functions agents can call
  • Code writing + execution — agents generate and run their own code
  • Group chat with planner — structured multi-agent collaboration with explicit sequencing

Lesson 1 — ConversableAgent & Two-Agent Conversation

What is an Agent in AutoGen?

An agent is an entity that acts on behalf of human intent. It can send and receive messages, perform actions, generate replies, and interact with other agents. The base class is ConversableAgent — a unified abstraction that covers all agent types.

ConversableAgent — Core Capabilities

  • LLM-based reply generation (pass one or more LLM configs)
  • Code execution
  • Function/tool execution
  • Human-in-the-loop support
  • Configurable termination/stopping logic

Each capability can be toggled on or off independently.

Basic Setup

from autogen import ConversableAgent

llm_config = {"model": "gpt-3.5-turbo"}

agent = ConversableAgent(
    name="chatbot",
    llm_config=llm_config,
    human_input_mode="NEVER",  # agent never asks for human input
)

human_input_mode options:

  • "NEVER" — fully autonomous, LLM generates all replies
  • "ALWAYS" — always prompts for human input before replying

generate_reply() — Stateless Single Call

reply = agent.generate_reply(
    messages=[{"content": "Tell me a joke.", "role": "user"}]
)

Important: generate_reply() does not alter internal agent state. Each call is independent — the agent has no memory of prior calls made this way. For stateful conversations, use initiate_chat().

Two-Agent Conversation with initiate_chat()

cathy = ConversableAgent(
    name="cathy",
    system_message="Your name is Cathy and you are a stand-up comedian.",
    llm_config=llm_config,
    human_input_mode="NEVER",
)

joe = ConversableAgent(
    name="joe",
    system_message="Your name is Joe and you are a stand-up comedian. "
                   "Start the next joke from the punchline of the previous joke.",
    llm_config=llm_config,
    human_input_mode="NEVER",
)

chat_result = joe.initiate_chat(
    recipient=cathy,
    message="I'm Joe. Cathy, let's keep the jokes rolling.",
    max_turns=2,
)

Agents maintain conversation state across turns. The system message customizes agent behavior and persona — without it, the agent behaves as a generic assistant.

Inspecting Chat Results

chat_result.chat_history   # full message log
chat_result.cost           # token usage and dollar cost
chat_result.summary        # conversation summary

Summary methods:

  • Default: returns the last message
  • summary_method="reflection_with_llm" + summary_prompt="Summarize the conversation" — calls the LLM post-conversation to produce a proper summary

Termination Conditions

Instead of a fixed max_turns, pass a Boolean function via is_termination_msg. Each agent checks incoming messages against the condition and stops replying when it triggers.

is_termination_msg=lambda msg: "I gotta go" in msg["content"]

Both agents should receive the termination condition so either one can end the conversation.

Continuing a Conversation (State Persistence)

After a conversation ends, you can resume it with agent.send(). Agents remember prior context — demonstrated by asking "What's the last joke we talked about?" and getting the correct answer.

cathy.send(message="What's the last joke we talked about?", recipient=joe)

Key Takeaways

  • generate_reply() = stateless, one-shot
  • initiate_chat() = stateful, multi-turn, memory preserved
  • System messages define agent persona and behavior
  • Termination can be fixed turns (max_turns) or condition-based (is_termination_msg)
  • Token usage and cost are tracked in chat_result.cost
Tool Use in Nested Chat Between Agents - Summary

Summary: Tool Use in Nested Chat Between Agents

Overview

This lesson demonstrates how to use tools inside nested chats in AutoGen by building a conversational chess game. Two AI agents act as chess players, and each player can call tools to inspect legal moves and make valid moves on the board. A third agent, the Board Proxy, executes the tools and manages the board state.

The main idea is that each player performs an internal nested chat with the board proxy before replying to the opposing player. This allows tool use to happen behind the scenes while the outer conversation remains natural and easy to follow. 

llm_config = {"model": "gpt-4-turbo"}

import chess
import chess.svg
from typing_extensions import Annotated

1. Setup

The lesson begins by setting up the language model configuration and importing the libraries needed to support the chess environment. GPT-4 Turbo is used because it performs better at chess than earlier models. The Python chess library is used to manage the board and legal moves. 

llm_config = {"model": "gpt-4-turbo"}

import chess
import chess.svg
from typing_extensions import Annotated

2. Initialize the Chess Board

A new chess board is created, and a boolean variable is initialized to track whether a move has been made. This variable is later used as part of the stopping condition for the board proxy agent. 

board = chess.Board()

made_move = False

3. Define the Needed Tools

Two tools are created for the chess game. The first tool returns all legal moves in UCI format. The second tool accepts a move in UCI format, updates the board, displays the board state, identifies the moved piece, and returns a readable description of the move.

Tool 1: Get Legal Moves

def get_legal_moves(
    
) -> Annotated[str, "A list of legal moves in UCI format"]:
    return "Possible moves are: " + ",".join(
        [str(move) for move in board.legal_moves]

Tool 2: Make a Move

def make_move(
    move: Annotated[str, "A move in UCI format."]
) -> Annotated[str, "Result of the move."]:
    move = chess.Move.from_uci(move)
    board.push_uci(str(move))
    global made_move
    made_move = True
    
    # Display the board.
    display(
        chess.svg.board(
            board,
            arrows=[(move.from_square, move.to_square)],
            fill={move.from_square: "gray"},
            size=200
        )
    )
    
    # Get the piece name.
    piece = board.piece_at(move.to_square)
    piece_symbol = piece.unicode_symbol()
    piece_name = (
        chess.piece_name(piece.piece_type).capitalize()
        if piece_symbol.isupper()
        else chess.piece_name(piece.piece_type)
    )
    return f"Moved {piece_name} ({piece_symbol}) from "\
    f"{chess.SQUARE_NAMES[move.from_square]} to "\
    f"{chess.SQUARE_NAMES[move.to_square]}."

4. Create Agents

Next, the lesson creates three agents:

  • Player White, who plays as white
  • Player Black, who plays as black
  • Board Proxy, who executes tools and stops when a move is completed

The player agents are given system instructions telling them to first check legal moves and then make a move. The board proxy does not use an LLM and instead acts as a control and execution layer. 

from autogen import ConversableAgent

# Player white agent
player_white = ConversableAgent(
    name="Player White",
    system_message="You are a chess player and you play as white. "
    "First call get_legal_moves(), to get a list of legal moves. "
    "Then call make_move(move) to make a move.",
    llm_config=llm_config,
)

# Player black agent
player_black = ConversableAgent(
    name="Player Black",
    system_message="You are a chess player and you play as black. "
    "First call get_legal_moves(), to get a list of legal moves. "
    "Then call make_move(move) to make a move.",
    llm_config=llm_config,
)

def check_made_move(msg):
    global made_move
    if made_move:
        made_move = False
        return True
    else:
        return False

board_proxy = ConversableAgent(
    name="Board Proxy",
    llm_config=False,
    is_termination_msg=check_made_move,
    default_auto_reply="Please make a move.",
    human_input_mode="NEVER",
)

5. Register the Tools

The tools must be registered for both the calling agents and the executing agent. In this case, each player can propose tool calls, and the board proxy executes them. AutoGen automatically creates the correct tool definitions from the Python functions and annotations. 

from autogen import register_function

for caller in [player_white, player_black]:
    register_function(
        get_legal_moves,
        caller=caller,
        executor=board_proxy,
        name="get_legal_moves",
        description="Get legal moves.",
    )
    
    register_function(
        make_move,
        caller=caller,
        executor=board_proxy,
        name="make_move",
        description="Call this tool to make a move.",
    )

player_black.llm_config["tools"]

6. Register the Nested Chats

Each player is configured with a nested chat that triggers when it receives a message from the opponent. Inside that nested chat, the board proxy starts a conversation with the player so the player can call the tools, make a move, and return the result. The outer conversation only sees the summary of that nested chat. 

player_white.register_nested_chats(
    trigger=player_black,
    chat_queue=[
        {
            "sender": board_proxy,
            "recipient": player_white,
            "summary_method": "last_msg",
        }
    ],
)

player_black.register_nested_chats(
    trigger=player_white,
    chat_queue=[
        {
            "sender": board_proxy,
            "recipient": player_black,
            "summary_method": "last_msg",
        }
    ],
)

7. Start the Game

Once everything is defined, a new board is created and the chess game begins. Player Black starts the chat by sending the message, “Let’s play chess! Your move.” Player White then triggers its nested chat with the board proxy, gets legal moves, selects one, and makes the move.

The lesson notes that GPT-4 is recommended for better results, and move choices may vary from run to run. 

board = chess.Board()

chat_result = player_black.initiate_chat(
    player_white,
    message="Let's play chess! Your move.",
    max_turns=2,
)

8. Adding Fun Chit-Chat

To make the game more engaging, the player agents are recreated with updated system messages that tell them to add friendly banter after each move. The tools are registered again, and the nested chats are set to silent=True so the inner tool-use conversation is hidden from view.

This results in a more entertaining outer conversation where the players not only make moves but also comment on the game and challenge one another.

If you want a human to participate in the game, you can enable manual input by setting human_input_mode="ALWAYS" for both player agents.

Main Takeaway

This lesson shows a practical pattern for combining tool use with nested chat. The player agents propose tool calls, the board proxy executes them, and the internal move-validation process stays hidden inside the nested chat. This makes it possible to create an experience that feels like a smooth conversation while still relying on structured tool-based actions in the background.

The example also shows how easily the experience can be extended, such as by adding chit-chat or human input, and sets the stage for more advanced tool-use patterns in later lessons.
